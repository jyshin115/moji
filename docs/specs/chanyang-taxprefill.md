# 스펙: 세무 자료로 사업장 정보 자동 채우기 (Tax-data Prefill)

> 제품: 모두의 지원금 (MOJI) — 5인 미만 영세사업장 대표 대상
> WhyTree: `docs/whytree/chanyang.md`
> 작성: 정찬양 (chanyang) / 2026-10-29 / `/grill-me` 2라운드(Q1~Q14) 결정 정리

## 1. 누구를 위한 기능인가, 문제는 언제 생기는가

- **사용자**: 상시근로자 5인 미만 영세사업장의 대표. 세무법인에 기장을 맡기고 있다.
- **문제가 생기는 순간**: 대표가 MOJI를 처음 열고 사업장 정보 입력 화면을 만났을 때.
  개업일·업종·매출·근로자 수를 일일이 적기 귀찮아 대충 적는다.
  틀린 정보로는 신청 가능 판정도 믿을 수 없다 (내 HW5 premortem 1·2번).
- **이 기능이 하는 일**: 세무법인이 이미 가진 자료(사업자등록 정보, 부가세·사업장현황 신고, 4대보험 인원)로
  판정에 필요한 5개 값을 미리 채운다. 대표는 **적지 않고 확인만** 한다.
- 세무사 직원이 쓰는 화면이 아니다. 세무 자료는 대표 대신 입력해 주는 수단이다.

## 2. 사용자가 단계별로 할 수 있는 일

1. 대표가 화면을 연다. 첫 줄에 **"세무법인이 가진 내 자료로 정보를 채우는 데 동의합니다"** 체크가 있다.
   체크 전에는 아무 값도 보이지 않는다.
2. 동의하면 5개 값이 채워진 채로 보인다. 각 칸에 **출처**가 붙는다 (예: "2025 부가세 신고").
3. 자료가 없거나, 1년이 넘었거나, 규칙으로 하나로 정할 수 없는 칸은 **"확인 필요"**로 표시된다.
   그 칸은 비어 있거나 후보 값만 들어 있다. 대표가 직접 고르거나 적는다.
   후보 값이 맞으면 그 칸의 **"맞아요"**를 눌러 확인한다 (출처는 그대로, "확인 필요"만 풀린다).
4. 대표가 아무 칸이나 고칠 수 있다. 고친 칸의 출처는 **"대표 수정"**으로 바뀐다.
5. 대표가 **"이대로 확인"**을 누르면 판정 입력용 프로필 JSON이 화면에 나온다.
   "확인 필요"가 남아 있으면 확인 버튼을 누를 수 없고, 남은 칸을 알려준다.

### 채우기 규칙 (출력은 희진 님 판정 입력과 같은 단위·선택지)

| 칸 | 단위·선택지 | 세무 자료 | 규칙 | "확인 필요"가 되는 경우 |
|---|---|---|---|---|
| 업종 | 음식점 / 제조 / 도소매 / 서비스업 | 사업자등록 업태 | **주업태**(첫 번째)로 매핑: 음식점업→음식점, 제조업→제조, 도매·소매업→도소매, 그 외→서비스업 | 업태가 둘 이상 (주업태로 채우되 표시) |
| 지역 | 서울 / 경기 / 부산 / 기타 | 사업장 소재지 | 주소 첫 단어(시·도) | 소재지 없음 |
| 업력 | 개월 | 개업일 | 개업일부터 **오늘**까지 개월 수, 내림 | 개업일 없음 |
| 연매출 | 억 원 | 부가세 신고 / 사업장현황신고 | 과세사업자: **직전 연도 부가세 과세표준 1기+2기 합계**. 면세사업자: **사업장현황신고 수입금액** | 신고 자료 없음, 1기·2기 중 하나만 있음, 자료가 1년 넘음 |
| 상시근로자 수 | 명 | 4대보험(고용보험) | **최근 12개월 고용보험 피보험자 월말 인원 평균, 대표 본인 제외, 소수점 내림** | 자료 없음 — **0으로 채우지 않는다** |

> 상시근로자를 0으로 채우면 "5인 미만"이 거짓으로 통과한다. 그래서 자료가 없으면 반드시 비워 둔다.

## 3. 이 기능이 서비스하는 WhyTree 노드

- **세무 자료로 자동 채우기** (이 기능 자체, ✦ SeedUp에 없는 방법)
  - 위로: 사업장 정보 입력 → 내가 신청 가능한 공고 알기 → 받을 수 있는 지원금 놓치지 않기 → 영세사업장이 버티고 클 자금 얻기
  - 점선(부가적인 why): 사업계획서 쓸 시간 줄이기 — 같은 숫자가 나중에 계획서 재무 항목에 쓰인다.

## 4. 범위 밖

- 홈택스·4대보험 공단과의 실제 연동 (프로토타입은 합성 샘플 JSON을 쓴다)
- 세무사·세무법인 직원용 화면
- 실제 거래처 데이터 (민감정보. 레포에 절대 올리지 않는다)
- 저장·로그인
- 신청 가능 판정 (희진 님 `docs/specs/heejin-eligibility.md`의 기능)
- 공고별 기준일(공고일·마감일)에 따른 업력 재계산 (판정 쪽 일)

## 5. 항목별 우선순위

### P0 (반드시)

- 동의 체크. 체크 전에는 값을 보여주지 않는다.
- 합성 샘플 사업장 3곳(정상 / 자료 누락 / 면세사업자) 중 하나를 골라 불러오기
- 위 표의 규칙으로 5개 값 채우기와 칸별 출처 표시
- "확인 필요" 표시. 상시근로자 자료가 없으면 0이 아니라 빈칸으로 둔다.
- 대표 수정 → 출처 "대표 수정"
- "이대로 확인" → 판정 입력용 프로필 JSON 표시. "확인 필요"가 남아 있으면 막는다.

### P1 (시간이 되면)

- 증명서 PDF·사진(사업자등록증명, 부가세 과세표준증명)을 AI로 읽어 같은 칸 채우기
- 업종코드 6자리 → 업종 매핑표
- 확인한 프로필을 희진 님 판정 화면으로 바로 넘기기

### P2 (나중에)

- 홈택스·4대보험 실제 연동 (대표 간편인증)
- 사업장 변화 감지 (예: 직원 증가 → 고용장려금 알림, WhyTree "사업장에 변화가 생기면 AI가 먼저 알려주기")
- 같은 재무 숫자를 사업계획서 초안에 넣기 (WhyTree "재무 숫자는 신고 자료에서 바로 넣기")

## 6. AI 모델과 실패 시 처리

- **P0는 AI를 쓰지 않는다.** 세무 자료는 이미 구조화된 숫자라서 규칙으로 채운다.
  같은 입력에는 항상 같은 값이 나와야 대표와 세무사가 믿을 수 있다.
- **P1 (증명서 PDF·사진 읽기)**: Claude `claude-opus-5-5`.
  - 모델은 증명서에서 글자 값(개업일, 소재지, 업태, 과세표준)만 뽑는다. 계산과 매핑은 위 규칙이 한다.
  - **실패할 때** (호출 오류, 시간 초과, 값을 못 찾음, 뽑은 값이 형식에 안 맞음):
    1. 그 칸은 비워 두고 "확인 필요 — 직접 입력"으로 표시한다.
    2. 추측한 값을 채워 넣지 않는다.
    3. 나머지 칸은 세무 자료 규칙대로 계속 채운다. 한 칸이 실패해도 화면 전체가 멈추지 않는다.

## 7. 손으로 하는 확인 3가지

합성 샘플의 기대값 (기준일 2026-10-29):

| 샘플 | 업종 | 지역 | 업력 | 연매출 | 상시근로자 |
|---|---|---|---|---|---|
| A 골목식당 (정상) | 음식점 | 서울 | 43개월 | 2.2억 | 3명 (37÷12=3.08) |
| B 동네꽃집 (누락) | 도소매 · 확인 필요 (업태 2개) | 경기 | 14개월 | 확인 필요 (2025 2기만 있음) | **빈칸 · 확인 필요** |
| C 바른수학학원 (면세) | 서비스업 | 부산 | 69개월 | 1.8억 (사업장현황신고) | 4명 (50÷12=4.17) |

1. **정상 사업장 값이 손계산과 같다.** A를 불러와 5개 값이 위 표와 같은지 본다.
   상시근로자는 월별 인원 12개를 직접 더하고 12로 나눠 대조한다. 동의 체크 전에는 값이 안 보이는지도 본다.
2. **없는 자료를 0으로 채우지 않는다.** B를 불러온다.
   상시근로자 칸이 0이 아니라 빈칸이고 "확인 필요"인지, 이 상태에서 "이대로 확인"이 막히는지 본다.
3. **출처가 맞고 수정이 반영된다.** C를 불러와 연매출 출처가 "사업장현황신고"인지 본다.
   연매출을 2.0으로 고치면 출처가 "대표 수정"으로 바뀌고, 확인 후 JSON에 2.0이 들어가는지 본다.

## 8. 팀과 맞출 것

- 동의 문구와 절차 (희진 님 스펙 8절에도 열려 있음)
- 상시근로자 기준: 소상공인 기준 "5인 미만"과 지원사업마다 다른 기준이 있을 수 있다. 공고별 기준은 판정 쪽에서 다룬다.
