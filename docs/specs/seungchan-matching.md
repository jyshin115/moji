## 누구를 위해, 어떤 순간에

상시근로자 5인 미만 영세사업장 대표. 경리·기획 담당이 없어 지원사업 공고를 찾는 일을 혼자 떠안는다.
"나도 신청할 수 있는 게 있나?"가 궁금하지만, 기업마당·소상공인24를 뒤질 시간이 없어 그냥 지나치는 순간.

## 사용자가 할 수 있는 것 (단계별)

1. 사업장 정보 4개를 입력한다: 업종(선택), 상시근로자 수(숫자), 소재지(시·도 선택), 개업연도(숫자).
2. "신청 가능 공고 찾기" 버튼을 누른다.
3. 결과를 본다:
   - **신청 가능** 공고가 상단에: 제목, 주관기관, 마감일, D-day 배지, 신청 방법 링크.
   - **신청 불가** 공고가 하단에: 미충족 조건 **전부**를 사유로 표시 (예: "상시근로자 5인 미만 조건 미충족").
   - 마감이 지난 공고는 "마감됨"으로 표시.
4. 입력을 바꿔 다시 누르면 결과가 갱신된다.

## 매칭 규칙

- 공고별 자격요건: 지역(시·도 목록), 업종(허용 목록), 상시근로자 수 상한, 최소/최대 업력(년).
- **AND 결합**: 명시된 조건을 모두 충족해야 "가능". 공고에 명시가 없는 조건은 "제한 없음"으로 통과.
  (희진님 `heejin-eligibility.md`의 AND 규칙과 동일 — 팀 빌드 때 합치기 쉽게.)
- 업력 = 오늘 연도 − 개업연도.
- 업종 선택지는 한국표준산업분류 대분류 기반 8개 + 기타:
  음식점·숙박업 / 도매·소매업 / 제조업 / 정보통신업 / 교육서비스업 / 보건·복지업 / 운수·물류업 / 개인서비스업 / 기타.

## 엣지 처리

- 근로자 수 0명(대표 혼자) 허용 — 1인 사업장이 핵심 타깃.
- 5인 이상 입력도 막지 않는다. 매칭 결과에서 불가 사유로 자연스럽게 드러낸다 (서비스가 거짓말하지 않는다).
- 빈 필드가 있으면 버튼을 눌렀을 때 해당 필드를 채우라고 안내.

## 범위 밖 (Out of scope)

- 실제 공고 자동 수집(크롤링) — 샘플 공고 10건을 하드코딩 (실제 공고 구조 참고).
- 알림 발송(이메일·카톡), 입력값 저장, 사업계획서 초안 연계.
- 선정 가능성 예측·순위 추천 — WhyTree에서 "하지 않기로 결정"한 노드.

## 우선순위

| 순위 | 항목 |
|---|---|
| **P0** | 4개 필드 입력 폼 → 매칭 실행 → 가능 공고 상단 / 불가 공고 하단 + 미충족 사유 전부 표시 |
| **P1** | D-day 배지, 마감임박(7일 이내) 강조, 마감 지난 공고 "마감됨" 처리, 모바일 대응 스타일 |
| **P2** | 실제 공고 자동 수집, 마감 알림 발송, 입력값 저장(localStorage), 초안 생성 연계 |

## AI 모델

런타임에 AI 모델을 쓰지 않는다 — 매칭은 규칙 기반(AND)이라 결과가 결정적이고, 실패 모드는 "데이터가 틀린 경우"뿐이다.
공고 데이터가 틀렸을 때의 대비: 각 공고 카드에 원문 링크를 두어 대표가 원문으로 확인할 수 있게 한다.
(AI는 개발 도구로만 사용: Claude Code로 스펙·구현·테스트.)

## 내 손으로 하는 테스트

1. **자격 매칭**: 서울 · 음식점·숙박업 · 근로자 2명 · 개업 2023 입력 → 자격이 맞는 공고만 상단 "신청 가능"에 뜬다. 업종·지역·업력이 안 맞는 공고는 하단에 사유와 함께 뜬다.
2. **근로자 수 변경**: 위 입력에서 근로자 수만 7명으로 변경 → "상시근로자 5인 미만" 조건이 있는 공고가 불가로 내려가고, 사유에 해당 조건이 표시된다.
3. **마감 처리**: 마감일이 지난 샘플 공고가 "마감됨"으로 표시되고 신청 가능 목록에 포함되지 않는다.
