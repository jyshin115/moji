# 스펙: 신청 가능 여부 판정·마감 알림 (Eligibility Check & Deadline Alert)

> 제품: 모두의 지원금 (MOJI) — 5인 미만 영세사업장 대표 대상
> WhyTree: `docs/whytree/heejin.md`
> 작성: 2026-10-29 / 상태: 초안 — 팀 확정 필요 항목은 ⚠️ 표시

## 1. 누구를 위한 기능인가, 문제는 언제 생기는가

- **사용자**: 상시근로자 5인 미만 영세사업장의 대표.
  경리나 기획 담당 직원이 없어 공고를 찾는 일도, 신청서를 쓰는 일도 혼자 떠안는다.
  파일럿은 세무법인 거래처 중 5인 미만 사업장 5곳이다.
- **문제가 생기는 순간**: 공고는 중기부·소상공인시장진흥공단·지자체·유관기관에
  흩어져 수시로 나오는데, 대표는 자기가 신청할 수 있는 공고가 무엇인지,
  마감이 언제인지, 어떤 서류로 어떻게 내는지 모른 채 지나친다.
  공고를 찾아도 사업계획서를 쓸 시간이 없어 포기하거나, 결국 연 100~200만 원짜리
  신청 대행 상품을 산다.
- **이 기능이 해결하는 것**: 대표가 사업장 정보를 한 번 넣으면,
  신청 가능한 공고만 골라 근거와 함께 보여주고, 마감을 놓치지 않게 알린다.
  선정 가능성 예측이나 순위 추천은 하지 않는다 (PROJECT.md 기준).

## 2. 사용자가 단계별로 할 수 있는 일

### 대표

1. 사업장 정보를 입력한다: 업종, 지역, 업력, 매출, 상시근로자 수.
   (⚠️ 세무법인 거래처 데이터로 입력을 대체하는 것은 동의 절차 확정 후)
2. 신청 가능 공고 목록을 본다. 각 공고마다 판정 결과와 근거를 본다.
3. "확인 필요"로 표시된 공고는 되묻는 질문에 답해 판정을 마저 채운다.
4. 신청하기로 한 공고는 마감 알림을 받는다. (⚠️ 알림 시점·채널은 팀 확정)
5. 신청을 결정하면 사업계획서 초안 단계로 넘어간다. (초안 작성은 별도 기능)

### 시스템

1. 사업장 정보를 저장한다.
2. 공고별로 5가지 조건(업종·지역·업력·매출·상시근로자 수)을 규칙으로 먼저 판정한다.
3. 판정은 3단계다: **신청 가능 / 확인 필요 / 해당 없음**.
4. 첨부문서(HWP·PDF)에서 뽑은 조건은 근거 문구와 위치를 함께 표시한다.
5. 마감 임박 공고는 알림 큐에 넣는다.
6. 판정 결과와 근거를 사업장별 기록에 남긴다.

### 판정 결합 규칙

- 5가지 조건(업종·지역·업력·매출·상시근로자 수)은 AND로 결합한다. 5가지 조건이 모두 충족될 때만 "신청 가능"이다.
- 5가지 조건 중 하나라도 충족되지 않으면 "해당 없음"이다.
  - 어느 조건도 충족되지 않은 것으로 확정되지 않았고, 하나라도 불확실하면 "확인 필요"이다.

## 3. 이 기능이 서비스하는 WhyTree 노드

- **어디에·언제·어떻게를 알게 하기** (핵심)
- **틀린 안내 안 하기** (신뢰 조건 — 틀린 추천은 대표도 우리도 믿지 못한다)
- **5인 미만 대표가 대행 없이 혼자 신청 끝내기** (상위 why)
- **영세사업장이 받을 수 있는 지원을 놓치지 않기** (최상위 why)

## 4. 범위에서 제외되는 것

- 선정 가능성 예측, 공고 순위 추천 (PROJECT.md에서 명시적으로 제외)
- 사업계획서 초안 작성 (별도 기능, 이 스펙의 범위 밖)
- 제출 서류 자동 준비, 선정 후 사후관리
- 정책자금(대출·이자 등) 안내 — MVP는 소상공인 대상 공고 중심 (⚠️ 범위 팀 확정)
- 공고 원문의 상업적 재배포 (약관·제공기관 확인 전에는 원문 링크 안내로 제한)

## 5. 항목별 우선순위

### P0 (반드시 배송)

- 사업장 정보 입력·저장 (업종·지역·업력·매출·상시근로자 수)
- 5가지 조건 규칙 매칭과 3단계 판정 (가능 / 확인 필요 / 해당 없음)
- 판정 근거 표시 (어느 조건이 맞았고, 어디에 적혀 있는지)
- 마감 알림 (⚠️ 시점·채널은 팀 확정, 제안: D-14/D-7/D-3)
- "확인 필요" 되묻기: 불확실한 조건을 확정 안내로 바꾸지 않고 질문으로 돌려보내기

### P1 (시간이 허락하면)

- 첨부문서 AI 추출 (조건·예외·표 관계 유지)과 사람 정리본 비교 리포트
  (QUESTIONS.md 3번 방식: 공고 30건 사람 정리 → 자동 추출과 맞은 비율·건당 검수 시간 측정)
- 알림 채널 연동 (⚠️ 카카오톡·문자 중 팀 확정)
- 수정 공고·조기 마감 반영 (기존 공고 변경 확인 절차)

### P2 (나중에)

- 세무법인 거래처 데이터 연동 (동의 기반 입력 대체)
- 제출 서류 체크리스트, 정책자금 범위 확장
- 사업장별 판정 이력 통계

## 6. 사용하는 AI 모델과 모델 오류 시 조치

- **모델**: gpt-6-luna (팀의 w07 워크플로에서 동작 확인된 모델).
- **모델이 하는 일**: 첨부문서에서 조건·예외·표 관계를 뽑는 추출 보조.
  명확한 조건(업종·지역·업력·매출·상시근로자 수)의 최종 판정은 규칙이 먼저 한다.
- **모델 오류 시 (추출 실패, 불확실한 출력, 원문과 어긋남)**:
  1. 그 조건은 "확인 필요"로 표시하고, 확정 안내를 내보내지 않는다.
  2. 절대로 불확실한 조건을 "신청 가능"으로 바꿔서 보여주지 않는다.
  3. 추출 결과는 사람 정리본과 대조하기 전에는 사용자에게 확정으로 보이지 않는다.
  4. 오류와 불확실 사례를 기록해, 나중에 추출 범위를 다시 정한다.
- **내 premortem 교훈의 반영**: "텍스트가 추출되면 파싱이 됐다"는 판단을
  이 스펙에서는 금지한다. 파싱 성공은 글자 추출이 아니라
  조건·예외·표의 관계가 유지됐는지로 판단한다.

## 7. 제대로 작동하는지 수동으로 확인하는 테스트 (3개)

테스트는 실제 손으로, 아래 순서대로 한다. 전부 통과해야 P0 완료이다.

### 테스트 1 — 해당 없음 제외

1. 지역이 서울인 사업장 프로필을 입력한다.
2. 지역 조건이 부산 전용인 샘플 공고를 넣는다.
3. 확인: 그 공고는 "해당 없음"으로 표시되고, 신청 가능 목록에 나오지 않는다.

### 테스트 2 — 마감 임박 알림

1. 마감이 7일 이내로 남은 신청 가능 공고를 만든다.
2. 확인: 알림 큐에 그 공고가 들어가고, 대표 화면에 마감 임박 표시가 뜬다.
3. 확인: 이미 지난 공고는 알림 큐에 들어가지 않는다.

### 테스트 3 — 불확실하면 확정 안내 금지

1. 조건이 표의 각주에만 있고 본문과 달라 보이는 샘플 공고를 넣는다.
2. 확인: 그 조건은 "확인 필요"로 표시되고, 되묻는 질문이 뜬다.
3. 확인: 대표가 답하기 전에는 그 공고가 "신청 가능"으로 바뀌지 않는다.
