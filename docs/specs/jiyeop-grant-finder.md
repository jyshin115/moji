## 1. 대상과 문제 발생 시점

5인 미만 영세사업장의 대표가 어떤 지원사업이 있는지, 우리 회사가 어떤 사업에 신청할 수 있는지 모르는 순간에 사용한다. 신청할 공고를 아직 정하지 않은 대표도 사용할 수 있다.

목표는 수록된 공고에서 회사 조건에 맞는 후보를 찾고, 판단 근거와 추가로 확인할 내용을 보여주는 것이다. 최종 신청 자격이나 선정 가능성을 보장하지 않는다.

## 2. 사용자와 결정한 내용

- 이번 개인 기능은 지원사업 찾기다. 사업계획서 초안 작성은 제외한다.
- 회사 기본 정보와 회사가 하는 일, 지금 필요한 도움을 입력받는다.
- 화면에서는 ‘지원 수요’ 대신 ‘지금 회사에 어떤 도움이 필요한가요?’라고 묻는다.
- ‘어떤 지원이 있는지 먼저 보고 싶어요’를 선택할 수 있다.
- 결과는 ‘입력 정보상 조건에 맞는 후보’와 ‘추가 확인이 필요한 후보’를 구분한다.
- 명확히 조건이 맞지 않는 사업은 기본 결과에서 제외한다.
- 공식 원문을 확인한 실제 공고 약 10건을 수록한다. 전체 지원사업을 검색한다고 표현하지 않는다.
- 자동 수집·갱신은 추후 업데이트다.
- 2026-10-27 사용자 요청에 따라 AI 관련성 설명을 P1으로 이동했다. P0는 AI·API 키·외부 서버 없이 동작한다.

## 3. 사용 순서

1. 검색 대상이 수록 공고로 제한됨과 공고 정보 확인일을 확인한다.
2. 소재지, 업종, 설립일, 직원 수, 매출액을 입력한다. 모르는 항목은 별도로 표시한다.
3. 회사가 하는 일과 필요한 도움을 짧게 입력한다. 필요한 도움이 정해지지 않았다면 전체 탐색을 선택한다.
4. 검색을 실행한다.
5. 후보별 사업명, 지원 내용, 마감일, 맞는 조건, 확인이 필요한 조건을 읽는다.
6. 원문 링크에서 상세 조건과 최신 공고 내용을 확인한다.
7. 입력 정보를 고쳐 다시 검색한다.

## 5. 조건 비교 규칙

- 조건별로 일치·불일치·정보 부족을 구분한다.
- 필수 조건 하나라도 명확히 불일치하면 기본 후보에서 제외한다. 다른 조건이 일치해도 이를 상쇄하지 않는다.
- 불일치는 없지만 사용자 정보나 공고의 조건이 불완전하면 ‘추가 확인이 필요한 후보’로 표시한다.
- 원문에 없거나 아직 확인하지 않은 조건을 임의로 충족 처리하지 않는다.
- 예외 조건·제외 업종 등 원문에서 확인이 필요한 항목을 결과에 표시한다.
- ‘모름’은 0이나 조건 충족으로 처리하지 않는다. 숫자 0과 빈칸은 구분한다.
- 기준일은 한국 날짜로 표시한다. 업력은 공고가 지정한 기준일을 우선하며, 기준일이 불명확하면 확인 필요로 둔다.
- 기간이 명시된 공고는 마감 여부를 판단한다. 예산 소진 시 종료 등 상태를 단정할 수 없는 공고는 원문 확인이 필요하다고 표시한다.
- AI 설명은 규칙으로 판단한 신청 조건을 변경하거나 불일치 공고를 통과시키지 않는다.
- 필요한 도움을 모르는 사용자를 특정 지원 분야로 임의 제한하지 않는다.

## 6. AI 사용과 실패 처리

- P0 AI 모델: 사용하지 않음. API 호출·키·비용이 없다.
- 사업 설명과 필요한 도움의 자유서술은 참고 메모로만 입력받는다. 자동 의미 분석이나 추천 근거로 사용하지 않음을 화면에 명시한다.
- 모르는 정보는 빈칸/‘모름’으로 처리한다. 검색 자체가 실패하면 입력 수정 안내를 보여준다.
- P1에서 AI 모델을 정하고 연결한다. 이후에도 관련성이 낮다는 이유만으로 기본 조건에 맞는 공고를 숨기지 않는다.
- 향후 AI 오류가 나면 기본 조건 결과를 유지하고 AI 설명만 제공 불가로 표시한다.

## 7. 직접 수행할 확인 3개

아래 검사는 사용자 본인이 수행한다. 에이전트의 자동 검사와 구분하며, 사용자 수행 전에는 통과했다고 기록하지 않는다. 화면의 ‘확인용 입력’ 버튼으로 예제 값을 불러온 뒤 ‘후보 찾기’를 누른다. 날짜가 지나도 재현할 수 있도록 별도 표시된 검증 모드에서는 2026-10-27을 기준으로 검사한다.

1. **조건 일치와 불일치:** ‘봉화 소매점’ 예제(경북 봉화군, 소매업, 직원 2명, 2025년 매출 2억원, 소상공인 해당)를 불러와 검색한다. 봉화군 카드수수료 공고가 나와야 한다. 매출을 4억원으로 바꾸면 해당 공고가 기본 후보에서 빠져야 한다. 원문 기준 3억원의 상한을 넘기 때문이다.
2. **정보 부족:** 위 예제의 매출을 빈칸으로 바꾸어 검색한다. 같은 공고에 ‘매출액 확인 필요’가 표시되어야 한다. 빈칸을 0으로 해석하지 않아야 한다.
3. **결과 없음과 복구:** 소상공인 해당 여부를 ‘해당하지 않음’으로 바꾸어 검색한다. ‘수록 공고 중 후보가 없습니다’가 나와야 한다. 다시 ‘해당’으로 바꾸면 후보가 복구되어야 한다. 기본 화면에서 마감된 스마트상점 공고가 제외되는지, 원문 링크가 열리는지도 확인한다.

직접 검사 결과(2026-10-27): 사용자가 첫 검사 수행 후 ‘응 전부 실행됐어’, 나머지 검사 안내 후 ‘전부 통과’라고 보고했다. 매출 초과 제외, 매출 미입력 안내, 결과 없음과 복구, 마감 공고 제외 및 원문 열기까지 통과로 기록한다. 보고된 실패는 없으며, 실패 사례를 회고에 만들어 넣지 않는다. 이번 검사 결과로 인한 기능 명세나 코드 변경은 없다.

## 8. 과제 제출 규칙

- 본인 파일과 prototypes/jiyeop/ 안에서만 작업한다. 공용 파일은 루트 .gitignore만 수정 가능하다.
- 루트 .gitignore에 node_modules/와 .env를 포함한다. 사용하는 다른 비밀정보 파일도 제외한다.
- 코드와 Git 이력에 비밀번호·API 키·.env가 없는지 확인한다.
- 지엽님이 수동 검사를 직접 수행하고, 발견한 문제는 명세서에 먼저 반영한 뒤 코드에 적용한다.
- push 전에 main을 pull한다. 본인 계정으로 commit·push하고 강제 push는 하지 않는다.
- 이번 HW6에서는 과제 안내에 따라 main에 제출하며 PR을 만들지 않는다.

## 9. 확정한 구현 범위

- AI 관련성이 낮아도 기본 조건에 맞는 후보는 유지한다. 현재는 AI를 사용하지 않는다.
- 로그인·서버·브라우저 영구 저장 없이 실행한다. 새로고침하면 입력을 초기화한다.
- 모든 파일은 prototypes/jiyeop/에 둔다. index.html을 브라우저로 직접 열면 실행된다.
- 본문에 지역 조건이 시군구 단위인 공고가 있어 시도와 시군구를 나누어 입력한다.
- 소상공인 자격은 직원 수만으로 단정할 수 없어 ‘소상공인 해당 여부’ 자기 확인 항목을 추가한다. 모르면 확인 필요로 처리한다.
- 2025년 매출 조건이 있는 공고에 맞춰 입력의 기준연도를 2025년으로 명시한다. 수록 공고에 업력 수치 조건이 없으면 설립일로 임의 필터링하지 않는다.
- 사업 설명·필요한 도움은 선택 입력 참고 메모다. 의미 기반 검색은 P1이다.
- 공고 데이터는 기업마당의 공식 공고 안내 페이지에서 확인한 기본 조건이다. 첨부 원문 전체를 파싱하지 않았으며, 제외 업종·중복 지원·증빙 등 미검증 조건을 별도로 표시한다. 이를 확인하지 않으면 ‘추가 확인 필요’로 분류한다.
- ‘수록 기본조건 일치’는 코드에 명시된 조건만 일치한다는 뜻이다. 최종 신청 가능 판정과 구분한다.
- 실제 날짜 모드가 기본이다. 테스트 예제를 불러오면 기준일을 2026-10-27로 고정하는 ‘검증 모드’가 켜지고, 과거 자료임을 화면에서 강조한다. 날짜를 숨기거나 과거 공고를 현재 모집 중이라고 표시하지 않는다.

## 10. 질문 세션 기록

- Matt Pocock의 공식 grill-me가 연결하는 grilling 지침을 읽고 이 대화에 적용했다. Claude Code의 슬래시 명령을 실행한 것으로 기록하지 않는다.
- 사용자는 Claude를 사용하지 않고 이 에이전트가 질문 과정을 진행하도록 요청했다.

- 용어 수정: 사용자가 ‘지원 수요’를 이해하기 어렵다고 하여 ‘지금 회사에 어떤 도움이 필요한가요?’로 바꾸었다.
- 범위 결정: 실시간 자동 수집 대신 수록 공고 검색을 먼저 구현하고 나머지는 추후 업데이트로 두었다.
- 구현 후 회고에 쓸 실패 사례나 테스트 결과는 실제 실행 후에만 기록한다.

## 11. 구현 전 범위 변경 기록

- 사용자 요청으로 AI 설명을 P0에서 P1으로 이동한 뒤 코드를 작성한다. API 설정·실시간 수집·공개 배포는 이번 제출에서 제외한다.
- 실제 공고 확인 결과, 소상공인 자격과 예외 조건은 단순 숫자 비교만으로 확정할 수 없어 확인 필요 항목을 추가했다.
- 일부 실제 공고가 이미 마감되어 있어 마감 필터와 명시적인 검증 기준일을 추가했다.
